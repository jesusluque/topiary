When a model doesn't fit, don't blur it — prune what it barely uses

The standard remedy for an oversized quantized model is fewer bits per weight: a uniform blur over every parameter. Topiary takes the orthogonal axis. It measures which neurons of which experts actually contribute on real traffic, bakes that ranking into the checkpoint as a free permutation, and cuts the file to a prefix. The damage concentrates on what the model barely used. That asymmetry is the entire advantage — and the output is a standard mlx-lm checkpoint: no custom kernels, no serving code, no training.

1 · Measure

Routed salience

salience²ᵢ = E[h²ᵢ] · ‖Wdown[:,i]‖², accumulated only over tokens the router sends to that expert. Collectable during normal serving at <1% overhead.

2 · Reorder

Free permutation

Permuting gate/up rows and down columns identically leaves the function exactly unchanged. Sort by importance, bake it into the file.

3 · Truncate

Cut to a prefix

The file is sorted, so cutting bytes = cutting what contributed least. k is a dial in steps of one quantization group.

The model can do this to itself, live

Because the statistic lives inside the forward pass, a serving model can profile itself on its own traffic and then permute and truncate its weights in RAM — 2.9 GB freed in about one second on a 30B model, no restart, no offline calibration phase. A layer-streaming profiler extends calibration to models larger than memory: an 80B profiled with a 1.1 GB peak.

# profile during serving, then convert
python src/runtime.py --model mlx-community/Qwen3-30B-A3B-4bit \
    --data data/calib.jsonl --profile-only --orders-out runs/orders.npz
python src/convert_block.py --src mlx-community/Qwen3-30B-A3B-4bit \
    --orders runs/orders.npz --k 576 --out models/my-model-w576

One serving caveat, stated plainly

Uniform-width builds load with stock mlx-lm — zero custom code. Per-layer-width builds (the flagship) need a ~30-line loader shim (src/per_layer.py) because a standard config cannot express different widths per layer. If that matters for your deployment, use the uniform sibling; the difference is a few points on generation benchmarks.

Honest limits — all measured, not speculated

  • Coarse experts lose. On Mixtral (8 experts of width 14336) bits win: over-parameterized experts absorb diffuse noise better than they survive amputation. The failure modes differ visibly — bits blur, width cuts produce confident-but-wrong logic.
  • There is a cliff. Quality collapses between 40–55% width reduction. Topiary is a mild-compression tool, not a miracle.
  • Tails favor bits. Benchmarks probing rare capabilities (MATH-500, HellaSwag) prefer bit-reduction, which keeps everything blurry-but-alive; truncation sacrifices what calibration never exercised.
  • ~3× compression is out of reach. Composing bits × width improves 5× over either axis alone, but a smaller native model still wins that regime.
  • Speed is not the lever. At equal bytes, ±3% tokens/s versus quantization on Apple Silicon batch-1 decode.

Hierarchy lives in the activations, not the weights — weight spectra are near-Gaussian, weight-only salience is nearly flat, and routed statistics beat whole-corpus calibration. Measured three independent ways.

Self-contained tools: online and streaming profilers, fine and block converters, per-layer allocation, a corpus builder and paired evaluators. Every number in the paper is reproducible from frozen configs.

Checkpoints

  • qwen3-30b-topiary — the flagship: fine build + per-layer depth taper. HumanEval 92%, GSM8K 94%, code PPL 2.64. Needs the 30-line loader shim.
  • qwen3-30b-topiary-w640 — uniform sibling: loads with stock mlx-lm, best MMLU (74%).
  • qwen3-30b-topiary-w576-code — code-calibrated, 13.1 GB: the original equal-bytes head-to-head winner.
